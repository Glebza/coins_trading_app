## Liquibase Fixes (deploy blockers)

### 1. `schema "backtests" does not exist`

**Cause:** `liquibase.liquibaseSchemaName=backtests` made Liquibase create tracking tables (`databasechangelog`) in `backtests` before changeSet `0-backtests-schema` created that schema.

**Fix:** `liquibase.liquibaseSchemaName=public` in `liquibase.backtest.properties` (app tables still in `backtests`).

### 2. `LIQUIBASE_VERSION` warning

Deploy scripts used `LIQUIBASE_VERSION` for the CLI install version; Liquibase 4.31+ treats it as an invalid env var.

**Fix:** renamed to `GLEBZA_LIQUIBASE_VERSION`; `unset LIQUIBASE_VERSION` before running Liquibase.

### 3. changeSet 29 — `max_capital_multiple NOT NULL`

**Cause:** Seed row `tinvest` inserted into `backtests.exchange` (changeSet 27) before changeSet 29 added `max_capital_multiple NOT NULL` without a default.

**Fix:** `defaultValueNumeric: 5.0` on addColumn in:

- `changelog/include/backtest/changelog-2.0.yaml` (changeSet 29)
- `changelog/include/changelog-2.0.yaml` (changeSet 24, public schema)

## Env File Permissions

**Problem:** deploy wrote `/etc/glebza/daily-loader.env` as `root:root` mode `600`. User `trader` could not `source` it for manual backfill:

```text
-bash: /etc/glebza/daily-loader.env: Permission denied
```

**Fix (code):** `remote-install.sh` now `chown ${GLEBZA_RUN_USER}:${GLEBZA_RUN_USER}` after write. Systemd units run as `User=trader`.

**One-time on existing server:**

```bash
sudo chown trader:trader /etc/glebza/daily-loader.env
sudo chmod 600 /etc/glebza/daily-loader.env
```

## How to Run on the Server

SSH as **`trader`** (same user as deploy).

### Initial historical backfill (manual)

```bash
cd /opt/glebza/daily_loader
set -a && source /etc/glebza/daily-loader.env && set +a
export PYTHONPATH=src

.venv/bin/python -m daily_loader sync-shares
.venv/bin/python -m daily_loader load-klines \
  --start-dt 2020-01-01T00:00:00+00:00 --end-dt 2026-06-15T00:00:00+00:00
.venv/bin/python -m daily_loader load-dividends \
  --start-dt 2020-01-01T00:00:00+00:00 --end-dt 2026-06-15T00:00:00+00:00
.venv/bin/python -m daily_loader load-ruonia \
  --start-dt 2020-01-01T00:00:00+00:00 --end-dt 2026-06-15T00:00:00+00:00
```

Alternative (after setting `BACKFILL_START_DT` / `BACKFILL_END_DT` in env):

```bash
sudo systemctl start daily-loader-backfill.service
journalctl -u daily-loader-backfill.service -f
```

### Daily incremental job

```bash
sudo systemctl start daily-loader.service
journalctl -u daily-loader.service -n 100
```

Timer runs `python -m daily_loader run` (sync-shares + 1-day kline/dividend/RUONIA window + volatility).

SSH key must be loaded (`ssh-add --apple-use-keychain ~/.ssh/id_ed25519` on macOS).
