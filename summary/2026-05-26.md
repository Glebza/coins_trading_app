## Manual RUONIA Insert

Use this to add or update one RUONIA row manually:

```sql
INSERT INTO backtests.funding_rates (
    rate_code,
    rate_date,
    annual_rate,
    source,
    status,
    published_at
)
VALUES (
    'RUONIA',
    DATE '2026-05-08',
    0.13860000,
    'cbr',
    'Standard',
    TIMESTAMP '2026-05-12 00:00:00'
)
ON CONFLICT (rate_code, rate_date, source) DO UPDATE
SET annual_rate = EXCLUDED.annual_rate,
    status = EXCLUDED.status,
    published_at = EXCLUDED.published_at;
```

For multiple rows:

```sql
INSERT INTO backtests.funding_rates (
    rate_code,
    rate_date,
    annual_rate,
    source,
    status,
    published_at
)
VALUES
    ('RUONIA', DATE '2026-05-07', 0.14070000, 'cbr', 'Standard', TIMESTAMP '2026-05-08 00:00:00'),
    ('RUONIA', DATE '2026-05-08', 0.13860000, 'cbr', 'Standard', TIMESTAMP '2026-05-12 00:00:00')
ON CONFLICT (rate_code, rate_date, source) DO UPDATE
SET annual_rate = EXCLUDED.annual_rate,
    status = EXCLUDED.status,
    published_at = EXCLUDED.published_at;
```

## Backtest Engine Carry Integration

Carry is wired into the backtest engine:

- `framework/volatility.py`
  - `estimate_annualized_return_volatility(...)`
- `framework/backtest/engine.py`
  - optional `dividends` and `funding_rates` inputs on `run_single_instrument_backtest(...)`
  - keeps pure EWMAC behavior when funding rates are absent
  - when funding data exists, adds carry columns and combines:

```text
combined_forecast = 50% combined EWMAC + 50% carry
```

- `framework/forecasts/combined_forecast.py`
  - `combine_ewmac_and_carry_forecast_series(...)`

- `framework/backtest/portfolio_engine.py`
  - loads dividends per instrument through `InstrumentDividendRepository`
  - loads funding rates once through `FundingRateRepository`
  - passes both into each single-instrument backtest
- `framework/backtest/plotting.py`
  - plots all `forecast_*` columns, including `forecast_carry`

## Lookahead Rules

For backtests:

- Dividend data should be usable only when `declared_date <= forecast_date` or, stricter, `api_created_at <= forecast_date`.
- RUONIA should be usable only when `published_at <= forecast_date`.

If `published_at` is unavailable, use a conservative next-business-day assumption before using the rate.
