### Portfolio module + backtest CLI

**[`framework/portfolio.py`](../glebza/tradeapp/src/framework/portfolio.py)**

- `create_equal_weight_portfolio(tickers, …)` loads shares via `TinvestRepository.list_shares_by_tickers`, builds equal weights, **persists** via `PortfolioRepository`, returns `Portfolio` with **`id`** set.
- Row keys from DB: `instruments_ticker`, `instrument_id`, `lot` (not `ticker`).
- Missing tickers: `missing = set(tickers) - {row["instruments_ticker"] for row in rows}`.
- **`block_value`** — Carver sizing (default `1.0`); **`lot_size`** — from `instrument_share.lot` (exchange lot). Not the same field.

**[`framework/backtest/portfolio_engine.py`](../glebza/tradeapp/src/framework/backtest/portfolio_engine.py)**

- Per-instrument loop moved from CLI into **`_run_portfolio_instrument_backtests`** (klines load + `run_single_instrument_backtest`).
- **`run_weighted_portfolio_backtest(portfolio, account, exchange, …)`** — always persists `backtest_runs`; requires **`portfolio.id`** (store portfolio before launch; no duplicate insert on run).
- Pass **`exchange`** row dict (from `ExchangeRepository`); `instrument_results=` optional for unit tests.
- **`BacktestRepository`** created inside engine; optional `backtest_repository=` for tests.

**[`framework/backtest/__main__.py`](../glebza/tradeapp/src/framework/backtest/__main__.py)** (portfolio-only CLI)

- **Universe:** `InstrumentsService.filter_shares()` — no `--tickers`; tickers come from DB filters.
- Loads **`exchange`** from `backtests.exchange` via `--exchange-code` (default `tinvest`).
- **`TradingAccount(..., exchange=exchange)`** — `commission_rate` and `max_capital_multiple` from DB, not CLI.
- CLI flags: `--volume-percentile`, `--volatility-percentile`, `--include-for-qual-investor`, `--strategy-id`, `--plot-path`, etc.
- Removed: `--tickers`, `--ticker`, `--persist`, `--limit`, `--commission-rate`, `--max-capital-multiple`, `--fixed-capital-at-risk`.
- Compounding is always on in the engine (capital at risk scales with equity).

**Universe filter** ([`instruments.py`](../glebza/tradeapp/src/framework/instruments/instruments.py) + [`tinvest_repository.py`](../glebza/tradeapp/src/repository/tinvest_repository.py)):

```text
1. Liquidity  — median kline volume ≥ cross-sectional percentile (default 60th)
2. Volatility — latest instrument_volatility ≥ percentile (default 60th)
3. Coverage   — kline count in [start_dt, end_dt] ≥ min_kline_coverage × expected bars (default 80%)
   → equal-weight portfolio → backtest
```

| **A1.3** | **RUONIA loader** | Done in code: `CbrRatesService.fetch_ruonia`, `FundingRateRepository.upsert_funding_rates`, `python -m manutil load-ruonia` |
| **A1.4** | **Carry rule** | `framework/forecasts/carry_forecast.py`; combine with EWMAC in `combined_forecast.py`; Liquibase seeds (`rules`, `rule_variations`, `strategy_rules`); engine + plots for carry columns |
| **A2** | **FDM** | Forecast diversification multiplier on combined forecasts before sizing; portfolio-level or per-rule-group |
| **A3** | **Out-of-sample backtesting** | In-sample vs hold-out windows (CLI flags e.g. train/test split dates, or metadata on `backtest_runs`); separate metrics on OOS segment |

**A1 open design:** carry input — rates/spreads in DB vs simplified proxy (e.g. roll from futures); must match what backtest DB can store.

### Phase B — Platform (after A)

| # | Item | Notes |
|---|------|--------|
| **B1** | **Single-DB consistency** | Confirm all writes use `backtests` (portfolios, klines, runs); no accidental `public` schema |
| **B2** | **Persist forecasts** | Batch or on-demand writes to `instrument_forecasts` (per variation + `combined_forecast`) |
| **B3** | **`backtest_run_series`** | Equity / return per bar in DB for replay without re-run |

### Pipeline (target)

```text
manutil: sync-shares → load-klines-all → update-volatility → load-ruonia
         ↓
filter_shares (liquidity → vol → kline coverage)
         ↓
equal-weight portfolio (persisted) → EWMAC + carry → FDM → combined forecast
         ↓
vol targeting → sizing → risk → portfolio backtest
         ↓
backtest_runs (+ optional OOS segment / instrument_forecasts / run_series)
```
