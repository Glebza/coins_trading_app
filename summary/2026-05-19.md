# Systematic Trading Framework Summary — 2026-05-19

This document updates [`2026-05-14.md`](2026-05-14.md) with work completed since then and the current improvement plan.

## Main Direction (unchanged)

Carver-style pipeline:

```text
Instrument selection
 -> Trading rules / forecasts
 -> Combined forecasts
 -> Volatility targeting
 -> Position sizing
 -> Portfolio construction
 -> Risk (trailing stop, notional cap)
 -> Execution / backtesting
```

Forecasts stay continuous (`-20..+20`); positions come from vol targeting, portfolio weights, capital at risk, and risk limits.

### Sizing and risk

- Volatility-targeted sizing in `framework/sizing.py` (`single_instrument_position_size`, `target_position_units` for bar-by-bar).
- Lot rounding (`round_position_to_lot` / `round_position_units`).
- Position inertia (`apply_position_inertia` / `apply_inertia_step`, default 10% band).
- Portfolio sleeve capital: `TradingAccount.allocate_capital(weight)` per ticker.
- Notional cap: `|position × close × block_value| ≤ capital_at_risk × max_capital_multiple` (on target and again on final position).
- **Compounding capital at risk (default):** each bar uses `capital_at_risk = initial_trading_capital × equity`; stored in backtest rows column `capital_at_risk`. Position size and P&L % scale down after losses.
- Trailing stop: `framework/risk/trailing_stop.py` — distance = `multiplier × price_volatility`; long exits below peak, short above trough; blocks same-side re-entry until forecast flips sign; combined with inertia in one bar loop.

## How Portfolio Results Are Structured

- **`PortfolioBacktestResult.rows`** — portfolio-level: per-ticker `strategy_return`, `{ticker}_weighted_return`, `portfolio_return`, `equity`, `drawdown`. No `position` column here.
- **`PortfolioBacktestResult.instrument_results[ticker].rows`** — full single-instrument table: `position`, `close_price`, `combined_forecast`, `capital_at_risk`, `equity`, etc.
- Plotting uses `instrument_results` for per-ticker notional; portfolio `rows` for equity and return.

## Capital at Risk (compounding)

```text
initial_capital = TradingAccount.trading_capital   # e.g. 100_000
equity[0] = 1.0

each bar t:
  capital_at_risk[t] = initial_capital * equity[t-1]
  size position from forecast using capital_at_risk[t]
  strategy_return[t] = P&L[t] / capital_at_risk[t]
  equity[t] = equity[t-1] * (1 + strategy_return[t])
```

Portfolio: each ticker compounds on its **sleeve** initial capital (e.g. 20k for weight 0.2), not the full 100k.

## Remaining Work (priority order)

### Risk and sizing (near term)

1. **Floor `price_volatility`** — minimum vol as % of price so quiet/cheap names do not request huge size before the notional cap.

3. **Portfolio gross exposure cap** (optional) — limit sum of `|notional|` across sleeves vs total capital.

## Notes from Backtest Analysis (2025 portfolio run)

- Use the **notional** panel (not raw shares) to compare exposure across tickers; cheap names can show huge share counts with moderate notional.
- With 5 equal-weight names and 100k capital, each sleeve starts at **20k** `capital_at_risk`; `max_capital_multiple=5` caps sleeve notional at **100k**.
- After drawdowns, compounding reduces `capital_at_risk` and position sizes automatically (unless `--fixed-capital-at-risk`).
- Trailing stop can flatten a sleeve; re-entry blocked until forecast sign changes.
