## What We Built / Changed (code)

### `glebza/transition_service` (new)

Sibling of `daily_loader` and `tradeapp`. Promotes a completed backtest run from `backtest` / `backtests` → `traderdb` / `public`.

| CLI | Purpose |
|-----|---------|
| `list-runs` | id, kline interval, annualised return, Sharpe, `started_at`, status |
| `promote --run-id N` | Copy exchange, instruments, strategy, portfolio, rules |
| `promote --run-id N --dry-run` | Validate without writing to `public` |

Env:

```bash
DATABASE_URL=postgresql://trader@.../backtest
DATABASE_DEFAULT_SCHEMA=backtests
LIVE_DATABASE_URL=postgresql://trader@.../traderdb
LIVE_DATABASE_DEFAULT_SCHEMA=public
```

Deploy: `glebza/deploy/deploy-transition-service.sh` → `/etc/glebza/transition-service.env`.

**Note:** `public` table is `strategy`; backtests uses `carver_strategy`. Live code reading `carver_strategy` still targets backtests until wired to `traderdb`.

### Password env for Liquibase

`LIQUIBASE_COMMAND_PASSWORD` is **not** a separate secret — it is the DB password for the user Liquibase connects as:

| Step | User | Set to |
|------|------|--------|
| Bootstrap | `postgres` | `PG_SUPERUSER_PASSWORD` |
| traderdb + backtest | `trader` | `TRADER_PASSWORD` (same as in `deploy.env` / `DATABASE_URL`) |

## Server Ops (2026-06-22 session)

### Migrations

Initial daily_loader deploy ran bootstrap + backtest only — **`traderdb` / `public` tables were missing** until `liquibase.properties update` was run manually or via `run-liquibase-migrations.sh`.

Verify:

```bash
psql "$DATABASE_URL" -c "SET search_path TO backtests; \dt backtests.carver_strategy"
psql "postgresql://trader@localhost/traderdb" -c "\dt public.strategy"
```

### Timezone

Server and Postgres were on `America/New_York`. Recommended **UTC** for ops alignment with kline timestamps (app code already uses `timezone.utc`; timer uses `21:30 UTC`).

```bash
sudo timedatectl set-timezone UTC
sudo -u postgres psql -c "ALTER SYSTEM SET timezone TO 'UTC';"
sudo -u postgres psql -c "ALTER SYSTEM SET log_timezone TO 'UTC';"
sudo systemctl reload postgresql
```

Timer schedule unchanged: `OnCalendar=Mon..Fri *-*-* 21:30:00 UTC`.

### daily_loader timer

**Problem:** `daily-loader.timer` was `enabled` but `inactive (dead)`, `Trigger: n/a` — never **started**.

**Fix:**

```bash
sudo systemctl daemon-reload
sudo systemctl enable daily-loader.timer
sudo systemctl start daily-loader.timer
systemctl list-timers daily-loader.timer
```

After fix: `active (waiting)`, next trigger visible (e.g. Mon 17:30 EDT = 21:30 UTC).

### systemd / logs

- Start service: **`sudo systemctl start daily-loader.service`** (not bare `systemctl start` — polkit prompts as admin user `skaldvent`).
- Logs: **`sudo journalctl -u daily-loader.service`** — user `trader` needs sudo or `systemd-journal` group.

### INVEST_TOKEN failure

First manual run failed:

```text
ValueError: INVEST_TOKEN is required
```

**Cause:** `/etc/glebza/daily-loader.env` missing or empty `INVEST_TOKEN`, or file not loaded (`EnvironmentFile=-/etc/glebza/daily-loader.env` — leading `-` ignores missing file silently).

**Fix:**

```bash
grep '^INVEST_TOKEN=' /etc/glebza/daily-loader.env   # must be non-empty
# or redeploy from laptop with INVEST_TOKEN in deploy.env
sudo chown trader:trader /etc/glebza/daily-loader.env
sudo chmod 600 /etc/glebza/daily-loader.env
sudo systemctl daemon-reload
```

Test before systemd:

```bash
set -a && source /etc/glebza/daily-loader.env && set +a
cd /opt/glebza/daily_loader && export PYTHONPATH=src
.venv/bin/python -m daily_loader check-tinvest
sudo systemctl start daily-loader.service
```
